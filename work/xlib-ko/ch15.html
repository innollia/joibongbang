15장. 리소스 관리자 함수 (Resource Manager Functions)

프로그램에는 글꼴, 색, 아이콘, 커서 같은 설정이 많이 필요하다. 이것을 전부 명령행 옵션으로 받기는 번거롭고, 사용자는 자기 취향을 "기본값"으로 저장해 두고 싶어 한다. 이를 위한 장치가 리소스 관리자(resource manager, Xrm)다. 설정은 보통 사람이 읽을 수 있는 파일(~/.Xresources, ~/.Xdefaults)이나 서버의 속성(루트 창의 RESOURCE_MANAGER, xrdb가 넣는다)에 저장된다.

리소스 관리자는 "비틀린" 데이터베이스다. 보통 데이터베이스는 대충 쓴 질의로 여러 레코드를 받지만, 리소스 관리자는 반대로 대충 쓴 규칙(와일드카드)으로 많은 값을 저장해 두고, 정확한 이름으로 질의해서 값 하나만 받는다. 예를 들어 "모든 창은 파란 배경, 그런데 메일 읽기 창만 빨간 배경"을 두 줄로 표현할 수 있다.

이름과 클래스

원문은 메일 프로그램 xmh로 설명한다. 응용은 이름 xmh, 클래스 Xmh를 갖는다(관례상 클래스는 대문자, 이름은 소문자로 시작). 그 안에 이름이 toc인 Paned 창, 그 안에 buttons라는 Box, 그 안에 incorporate라는 Command 버튼이 있다면:

  • 버튼의 완전한 이름: xmh.toc.buttons.incorporate
  • 버튼의 완전한 클래스: Xmh.Paned.Box.Command

이름과 클래스의 구성 요소 수는 항상 같다. 여기에 속성(attribute)이 붙는다. 활성 상태 전경색이라면 이름은 activeForeground, 클래스는 Foreground일 수 있다. 응용이 리소스를 찾을 때는 이 완전한 이름과 클래스를 넘기고, 리소스 관리자는 데이터베이스의 불완전한 규칙들과 비교해 가장 잘 맞는 값을 돌려준다. 정의는 <X11/Xresource.h>에 있다.

15.1 리소스 파일 문법 (Resource File Syntax)

ResourceLine  = Comment | IncludeFile | ResourceSpec | <빈 줄>
Comment       = "!" {줄바꿈·널을 뺀 아무 문자}
IncludeFile   = "#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
ResourceSpec  = WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName  = [Binding] {Component Binding} ComponentName
Binding       = "." | "*"
Component     = "?" | ComponentName
ComponentName = NameChar {NameChar}
NameChar      = "a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value         = {널과 이스케이프되지 않은 줄바꿈을 뺀 아무 문자}
  • 주석은 !로 시작한다(#가 아니다. #은 include에 쓰인다).
  • #include "파일": 그 줄을 파일 내용으로 바꾼다. include는 소문자여야 하고, 상대 경로는 그 줄이 있는 파일의 디렉터리 기준이다.
  • 바인딩 문자가 둘 이상 이어지면, 모두 .이면 . 하나로, 하나라도 *이면 * 하나로 바뀐다.
  • 같은 ResourceName이 여러 번 나오면 마지막 줄이 쓰인다. 데이터베이스에는 같은 이름의 항목이 둘 있을 수 없다.
  • 이름·콜론 앞뒤 공백은 무시된다. 값 안의 특수 표기:
    • \+공백, \+탭: 값이 공백·탭으로 시작하게 할 때
    • \n: 줄바꿈 문자
    • \+줄바꿈: 줄 이어 쓰기(둘 다 제거됨)
    • \nnn(8진수 세 자리): 임의의 바이트
    • \\: 역슬래시 하나
! ~/.Xresources 예
*background:            gray90
xterm*foreground:       black
xterm.vt100.font:       -misc-fixed-medium-r-normal--14-*-*-*-*-*-iso10646-1
myapp*Button.label:     \ 앞에 공백이 있는 라벨
myapp.message:          첫 줄\n둘째 줄
#include "colors.ad"

15.2 매칭 규칙 (Resource Manager Matching Rules)

질의는 항상 이름과 클래스를 완전히 지정해야 한다(*, ? 사용 불가). 한 이름·클래스는 최대 100개 구성 요소까지 지원한다. 반대로 데이터베이스 항목은 패턴을 쓴다.

  • * (느슨한 결합, loose binding): 중간 구성 요소 0개 이상을 건너뛴다.
  • . (단단한 결합, tight binding): 바로 붙은 두 구성 요소를 잇는다.
  • ?: 구성 요소 하나(이름이든 클래스든)와 맞는다.
  • 항목은 느슨한 결합으로 끝날 수 없고, 마지막 구성 요소는 ?일 수 없다.

여러 항목이 맞으면, 이름·클래스를 왼쪽(상위)부터 한 단계씩 보며 다음 규칙을 순서대로 적용해 하나만 남을 때까지 걸러낸다.

  1. 그 단계에서 구성 요소(이름, 클래스, ?)가 실제로 맞은 항목이, *로 그 단계를 건너뛴 항목보다 우선한다.
  2. 이름이 맞은 항목 > 클래스가 맞은 항목 > ?로 맞은 항목.
  3. 앞에 .(단단한 결합)이 있는 항목 > *(느슨한 결합)이 있는 항목.

원문의 예:

xmh*Paned*activeForeground:         red     (A)
*incorporate.Foreground:            blue    (B)
xmh.toc*Command*activeForeground:   green   (C)
xmh.toc*?.Foreground:               white   (D)
xmh.toc*Command.activeForeground:   black   (E)

질의 이름:  xmh.toc.messagefunctions.incorporate.activeForeground
질의 클래스: Xmh.Paned.Box.Command.Foreground
  • 1단계(xmh/Xmh): B는 이 단계를 *로 건너뛰었으므로 규칙 1로 탈락.
  • 2단계(toc/Paned): A는 클래스 Paned로, 나머지는 이름 toc으로 맞으므로 규칙 2로 A 탈락.
  • 3단계(messagefunctions/Box): 남은 C, D, E 모두 *로 건너뛰므로 변화 없음.
  • 4단계(incorporate/Command): D는 ?, C와 E는 클래스 Command로 맞으므로 규칙 2로 D 탈락.
  • 5단계(activeForeground/Foreground): E는 ., C는 *로 이어지므로 규칙 3으로 C 탈락. 결과는 E(black).
요점은 "왼쪽에서 먼저 구체적인 것이 이긴다"는 것이다. 전체 길이가 길다고 이기는 것이 아니다. 사용자가 "왜 내 설정이 안 먹지?" 할 때 대부분 더 상위 단계에서 더 구체적인 다른 항목이 있기 때문이다.

15.3 쿼크 (Quarks)

리소스 관리자는 툴킷에서 아주 많이 불리므로, 매번 문자열을 비교하면 느리다. 그래서 문자열을 정수 별칭인 쿼크(XrmQuark)로 바꿔 정수 비교로 처리한다. 서버의 아톰(atom)과 비슷하지만 쿼크는 순전히 내 프로세스 안에서만 쓰인다.

typedef int XrmQuark, *XrmQuarkList;
typedef XrmQuark XrmName, XrmClass, XrmRepresentation;
#define NULLQUARK ((XrmQuark) 0)
typedef XrmQuarkList XrmNameList, XrmClassList;   /* NULLQUARK로 끝나는 배열 */

XrmQuark XrmUniqueQuark(void);
XrmQuark XrmStringToQuark(char *string);
XrmQuark XrmPermStringToQuark(char *string);
char    *XrmQuarkToString(XrmQuark quark);
void     XrmStringToQuarkList(char *string, XrmQuarkList quarks_return);
XrmStringToBindingQuarkList(char *string, XrmBindingList bindings_return,
                            XrmQuarkList quarks_return);
  • XrmUniqueQuark: 어떤 문자열에도 대응하지 않는 새 쿼크.
  • XrmStringToQuark: 문자열→쿼크. 넘긴 문자열은 호출 뒤 버려도 된다. XrmPermStringToQuark는 "이 문자열은 영원히 살아 있다"고 Xlib에 약속하는 판이라, 복사하지 않고 그 주소를 XrmQuarkToString의 결과로 그대로 쓸 수 있다(문자열 상수에 쓰면 메모리 절약). XrmStringToName, XrmStringToClass, XrmStringToRepresentation은 같은 함수의 별칭 매크로다.
  • XrmQuarkToString: 쿼크→문자열. 돌려받은 문자열은 고치거나 해제하지 않는다. 대응 문자열이 없으면 NULL. 같은 쿼크에 대해 항상 같은 주소를 돌려준다.
  • XrmStringToQuarkList: "a.b.c" 같은 이름을 쿼크 배열로 쪼갠다. 배열 공간은 호출자가 넉넉히 준비한다.
  • XrmStringToBindingQuarkList: 쿼크 배열과 함께 각 구성 요소 앞의 결합(XrmBindTightly=., XrmBindLoosely=*) 배열도 돌려준다. 맨 앞에 바인딩이 없으면 단단한 결합으로 본다. 예: "*a.b*c" → 쿼크 a, b, c / 결합 loose, tight, loose.

15.4 데이터베이스 만들기와 저장 (Creating and Storing Databases)

데이터베이스는 불투명 타입 XrmDatabase이고, 값은 XrmValue에 담긴다.

typedef struct {
    unsigned int size;   /* 바이트 수 */
    XPointer     addr;   /* 값의 주소 */
} XrmValue, *XrmValuePtr;

값마다 붙는 표현 타입(representation type)은 응용이 정하는 꼬리표(예: "String", "Color")이고, C 타입이나 클래스와는 관계가 없다. 파일이나 명령행에서 읽은 값은 모두 "String"이다.

void        XrmInitialize(void);
XrmDatabase XrmGetFileDatabase(char *filename);
void        XrmPutFileDatabase(XrmDatabase database, char *stored_db);
char       *XResourceManagerString(Display *display);
char       *XScreenResourceString(Screen *screen);
XrmDatabase XrmGetStringDatabase(char *data);
char       *XrmLocaleOfDatabase(XrmDatabase database);
void        XrmDestroyDatabase(XrmDatabase database);
void        XrmSetDatabase(Display *display, XrmDatabase database);
XrmDatabase XrmGetDatabase(Display *display);
  • XrmInitialize: 리소스 관리자를 초기화한다. 다른 Xrm 함수보다 먼저 부른다.
  • XrmGetFileDatabase: 파일을 읽어 새 데이터베이스를 만든다. 현재 로캘로 해석하고, 데이터베이스도 현재 로캘에 묶인다. 파일을 못 열면 NULL. 문법이 틀린 파일의 결과는 구현마다 다르다.
  • XrmPutFileDatabase: 데이터베이스를 파일로 저장한다(데이터베이스의 로캘로). 순서는 구현마다 다르고, 표현 타입이 "String"이 아닌 항목은 저장되지 않는다.
  • XResourceManagerString: 연결을 열 때 받아 둔 0번 화면 루트 창의 RESOURCE_MANAGER 속성(xrdb로 넣은 사용자 설정)을 현재 로캘로 바꾼 문자열. Xlib 소유이므로 해제하지 않는다. 없으면 NULL.
  • XScreenResourceString: 특정 화면 루트 창의 SCREEN_RESOURCES 속성. 이쪽은 호출자가 XFree해야 한다(위 함수와 반대이니 주의).
  • XrmGetStringDatabase: 널로 끝나는 문자열에서 데이터베이스를 만든다(XResourceManagerString 결과를 넘기는 용도로 자주 쓴다).
  • XrmLocaleOfDatabase: 데이터베이스에 묶인 로캘 이름(Xlib 소유).
  • XrmDestroyDatabase: 해제. NULL이면 그냥 돌아온다.
  • XrmSetDatabase/XrmGetDatabase: 데이터베이스를 디스플레이에 붙여 두고 꺼낸다. 새로 붙일 때 예전 것은 해제되지 않는다. 아직 붙인 것이 없으면 XrmGetDatabase는 NULL. XGetDefault(부록 D)도 이 데이터베이스를 쓴다.

15.5 데이터베이스 합치기 (Merging Resource Databases)

Status XrmCombineFileDatabase(char *filename, XrmDatabase *target_db, Bool override);
void   XrmCombineDatabase(XrmDatabase source_db, XrmDatabase *target_db, Bool override);
void   XrmMergeDatabases(XrmDatabase source_db, XrmDatabase *target_db);
  • override가 True면 같은 이름의 항목은 원본(파일/source)이 덮어쓰고, False면 원본 쪽을 버린다.
  • *target_db가 NULL이면 새로 만들어(또는 source를 그대로) 넣어 준다.
  • XrmCombineDatabase/XrmMergeDatabases는 source_db를 파괴한다. 합친 뒤 source_db를 다시 쓰거나 해제하면 안 된다.
  • XrmMergeDatabases는 override=True인 XrmCombineDatabase와 같다.
  • XrmCombineFileDatabase는 파일을 못 읽으면 0을 돌려준다.
  • 항목은 값·타입 변환 없이 합쳐지며, 대상의 로캘은 바뀌지 않는다.

"나중에 덮어쓴 것이 이긴다"를 이용하면 우선순위를 쉽게 만들 수 있다: 응용 기본값 → 서버의 RESOURCE_MANAGER(또는 ~/.Xdefaults) → 명령행 옵션 순으로 합치면 명령행이 가장 강하다.

15.6 리소스 찾기 (Looking Up Resources)

Bool XrmGetResource(XrmDatabase database, char *str_name, char *str_class,
                    char **str_type_return, XrmValue *value_return);
Bool XrmQGetResource(XrmDatabase database, XrmNameList quark_name,
                     XrmClassList quark_class, XrmRepresentation *quark_type_return,
                     XrmValue *value_return);

목적: 완전한 이름·클래스로 값을 찾는다. 찾으면 True.

  • 돌려받는 값과 타입은 데이터베이스 내부 메모리를 가리키므로 고치면 안 된다.
  • 데이터베이스는 XrmPutResource, XrmQPutResource, XrmMergeDatabases 때만 항목을 해제·덮어쓴다. 새로 넣거나 합치지 않는 한, 받은 주소는 프로그램이 끝날 때까지 안전하다. 반대로 값을 넣거나 합친 뒤에는 예전에 받은 주소를 믿지 말고 다시 찾는다.
  • 문자열 값은 value.addr를 char *로 바꿔 쓴다.

툴킷은 보통 "마지막 구성 요소만 다른" 질의를 1~20번 연달아 한다. XrmGetResource는 최악 2n(n은 이름 길이)이 걸리므로, 앞부분이 같은 질의를 여러 번 할 때는 미리 검색 목록을 만들어 두면 빠르다.

Bool XrmQGetSearchList(XrmDatabase database, XrmNameList names, XrmClassList classes,
                       XrmSearchList list_return, int list_length);
Bool XrmQGetSearchResource(XrmSearchList list, XrmName name, XrmClass class,
                           XrmRepresentation *type_return, XrmValue *value_return);
  • XrmQGetSearchList: 공통 앞부분(이름·클래스)에 대해 일치 가능성이 있는 데이터베이스 단계 목록을 좋은 순서대로 만든다. list_length는 항목 개수(바이트 아님)이고 최악의 경우 3n개가 필요하다. 공간이 모자라면 False. 앞부분만 넘겨야 한다는 점에 주의한다.
  • XrmQGetSearchResource: 그 목록에서 마지막 구성 요소 하나로 값을 찾는다. 첫 일치에서 멈추며, 결과는 전체 이름으로 XrmQGetResource를 한 것과 같다.
원문 변환본에는 XrmQGetSearchList의 원형이 XrmQGetSearchResource라는 이름으로 잘못 적혀 있다. 위 원형이 올바른 것이다.

15.7 데이터베이스에 넣기 (Storing into a Resource Database)

void XrmPutResource(XrmDatabase *database, char *specifier, char *type, XrmValue *value);
void XrmQPutResource(XrmDatabase *database, XrmBindingList bindings, XrmQuarkList quarks,
                     XrmRepresentation type, XrmValue *value);
void XrmPutStringResource(XrmDatabase *database, char *specifier, char *value);
void XrmQPutStringResource(XrmDatabase *database, XrmBindingList bindings,
                           XrmQuarkList quarks, char *value);
void XrmPutLineResource(XrmDatabase *database, char *line);
  • 모두 XrmDatabase *(포인터의 포인터)를 받는다. *database가 NULL이면 새 데이터베이스를 만들어 넣어 준다. 그래서 XrmDatabase db = NULL;로 시작해 바로 넣어도 된다.
  • 값은 데이터베이스 안으로 복사되므로, 넘긴 버퍼는 호출 뒤 재사용해도 된다.
  • specifier는 "*background"처럼 와일드카드를 포함한 부분 지정이다. XrmPutResource는 내부에서 XrmStringToBindingQuarkList를 부른 뒤 XrmQPutResource를 부르는 편의 함수다.
  • XrmPutStringResource는 타입 "String"으로 넣는 편의 함수, XrmQPutStringResource는 strlen으로 크기를 계산해 넣는다.
  • XrmPutLineResource: "xterm*background: black" 같은 한 줄을 그대로 넣는다. 데이터베이스의 로캘로 해석하며, 주석 줄은 저장되지 않는다.
  • 같은 결합·쿼크의 항목이 이미 있으면 타입과 값이 바뀐다.

15.8 항목 나열 (Enumerating Database Entries)

#define XrmEnumAllLevels 0
#define XrmEnumOneLevel  1

Bool XrmEnumerateDatabase(XrmDatabase database, XrmNameList name_prefix,
                          XrmClassList class_prefix, int mode,
                          Bool (*proc)(), XPointer arg);

/* proc 의 모양 */
Bool proc(XrmDatabase *database, XrmBindingList bindings, XrmQuarkList quarks,
          XrmRepresentation *type, XrmValue *value, XPointer arg);

목적: 주어진 이름·클래스 앞부분을 어떻게든 완성하면 맞게 되는 항목마다 proc을 부른다. 순서는 구현마다 다르다.

  • XrmEnumOneLevel: 앞부분 뒤에 이름·클래스가 정확히 하나 더 붙는 항목만. XrmEnumAllLevels: 하나 이상 붙는 모든 항목.
  • proc이 True를 돌려주면 나열을 멈추고 함수도 True를 돌려준다. 끝까지 False면 함수도 False.
  • bindings와 quarks는 NULLQUARK로 끝난다. database와 type은 포인터로 오지만 고치면 안 된다. proc 안에서 데이터베이스를 고치면 안 되며, 스레드 모드에서는 데이터베이스가 잠긴 채 불리므로 같은 데이터베이스로 다른 Xlib 함수를 부르면 결과가 정의되지 않는다.
원문 변환본에는 두 상수가 모두 0으로 적혀 있는데, 실제 <X11/Xresource.h>에서는 XrmEnumAllLevels가 0, XrmEnumOneLevel이 1이다. 숫자 대신 헤더의 이름을 쓰면 문제없다.

15.9 명령행 옵션 해석 (Parsing Command Line Options)

typedef enum {
    XrmoptionNoArg,      /* 값은 표의 value 필드 */
    XrmoptionIsArg,      /* 값은 옵션 문자열 자신 */
    XrmoptionStickyArg,  /* 값은 옵션 바로 뒤에 붙은 글자들 */
    XrmoptionSepArg,     /* 값은 다음 argv 원소 (-fn fixed) */
    XrmoptionResArg,     /* 다음 argv 원소가 "리소스: 값" 한 줄 (-xrm) */
    XrmoptionSkipArg,    /* 이 옵션과 다음 인자를 무시 */
    XrmoptionSkipLine,   /* 이 옵션과 나머지 argv 전부 무시 */
    XrmoptionSkipNArgs   /* 이 옵션과 그 뒤 value개 인자 무시 */
} XrmOptionKind;

typedef struct {
    char         *option;     /* argv에서 찾을 옵션 문자열 */
    char         *specifier;  /* 결합 문자 + 리소스 이름 (응용 이름 제외) */
    XrmOptionKind argKind;
    XPointer      value;      /* NoArg, SkipNArgs 일 때 쓰는 값 */
} XrmOptionDescRec, *XrmOptionDescList;

void XrmParseCommand(XrmDatabase *database, XrmOptionDescList table, int table_count,
                     char *name, int *argc_in_out, char **argv_in_out);

목적: 옵션 표에 따라 argc/argv를 해석해 데이터베이스에 넣고, 알아본 옵션을 argv에서 지운다. XrmoptionSkipArg는 value가 1인 XrmoptionSkipNArgs와 같고, SkipNArgs의 value가 0이면 옵션 자신만 건너뛴다.

  • 항목은 name(응용 이름) + specifier로 저장된다. 사이에 결합 문자를 넣어 주지 않으므로 specifier는 반드시 .이나 *로 시작해야 한다. name에 점이 있어도 구성 요소 하나로 취급한다.
  • 모든 항목은 타입 "String"으로, argv에 나온 순서대로 들어간다. *database가 NULL이면 현재 로캘로 새로 만든다. 옵션 비교는 로캘과 무관한 바이트 비교이고 대소문자를 구분한다.
  • 모호하지 않은 줄임말도 받아 준다(예: 표에 -geometry만 있으면 -geom도 통한다).
  • *argc_in_out은 남은 인자 개수로 바뀐다.

원문의 예시 표는 -bg/-background → *background, -fn → *font, -geometry → .TopLevelShell.geometry, -iconic → .TopLevelShell.iconic(NoArg, "on"), -xrm → ResArg 같은 표준 X 옵션들을 보여 준다. *background는 모든 background 속성에 걸리고, .TopLevelShell.borderWidth는 최상위 창에만 걸린다는 차이를 눈여겨보면 된다.

예제: 기본값 + 사용자 설정 + 명령행을 합쳐 값 읽기

/* cc xrm.c -lX11 ;  ./a.out -bg yellow -xrm "demo*title: hello" */
#include <stdio.h>
#include <stdlib.h>
#include <X11/Xlib.h>
#include <X11/Xresource.h>

static XrmOptionDescRec opts[] = {
    { "-bg",    "*background",   XrmoptionSepArg, NULL },
    { "-fg",    "*foreground",   XrmoptionSepArg, NULL },
    { "-title", ".title",        XrmoptionSepArg, NULL },
    { "-rv",    "*reverseVideo", XrmoptionNoArg,  (XPointer) "on" },
    { "-xrm",   NULL,            XrmoptionResArg, NULL },
};

static const char *get(XrmDatabase db, const char *name, const char *cls,
                       const char *def)
{
    char *type; XrmValue v;
    if (XrmGetResource(db, (char *)name, (char *)cls, &type, &v) && v.addr)
        return (const char *) v.addr;
    return def;
}

int main(int argc, char **argv)
{
    XrmInitialize();

    /* 명령행은 디스플레이를 열기 전에 해석해도 된다 */
    XrmDatabase cmd = NULL;
    XrmParseCommand(&cmd, opts, sizeof opts / sizeof opts[0], "demo", &argc, argv);

    Display *dpy = XOpenDisplay(NULL);
    if (!dpy) return 1;

    /* 1) 응용 기본값 */
    XrmDatabase db = XrmGetStringDatabase("demo*background: white\n"
                                          "demo*foreground: black\n");
    /* 2) 사용자 설정: 서버 속성, 없으면 ~/.Xdefaults */
    char *s = XResourceManagerString(dpy);           /* 해제하지 않는다 */
    XrmDatabase user = NULL;
    if (s) user = XrmGetStringDatabase(s);
    else {
        char path[1024];
        const char *home = getenv("HOME");
        snprintf(path, sizeof path, "%s/.Xdefaults", home ? home : ".");
        user = XrmGetFileDatabase(path);             /* "~" 는 확장되지 않는다 */
    }
    if (user) XrmMergeDatabases(user, &db);         /* user 는 이제 쓰면 안 됨 */
    /* 3) 명령행이 가장 강하다 */
    if (cmd) XrmMergeDatabases(cmd, &db);

    printf("background = %s\n", get(db, "demo.background", "Demo.Background", "?"));
    printf("title      = %s\n", get(db, "demo.title", "Demo.Title", "(none)"));
    printf("남은 인자 %d개\n", argc - 1);

    XrmDestroyDatabase(db);
    XCloseDisplay(dpy);
    return 0;
}
흔한 함정
  • XrmGetResource에 "demo*background"처럼 와일드카드를 넣는 실수. 질의는 항상 완전한 이름·클래스다.
  • 이름과 클래스의 구성 요소 수가 다르면 제대로 맞지 않는다.
  • 파일 경로의 ~는 셸이 확장하는 것이라 Xrm 함수는 모른다. getenv("HOME")으로 직접 만든다.
  • 합치기 함수가 source를 파괴한다는 점을 잊고 다시 XrmDestroyDatabase하면 이중 해제가 된다.
  • XResourceManagerString은 해제하지 않고, XScreenResourceString은 XFree한다. 짝이 반대다.
