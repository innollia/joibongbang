부록 D. 호환성 함수 (Compatibility Functions)

이 부록의 함수들은 낡았고(obsolete), 더 새로운 X11 함수로 대체되었으며, 오래된 코드와의 호환을 위해서만 남아 있다. 새 코드에서는 쓰지 말고, 옛 코드를 읽거나 고칠 때 "이건 요즘 무엇으로 바꾸면 되나"를 찾는 용도로 보면 된다. 왜 바뀌었나? 대부분은 창 관리자와의 약속(ICCCM)이 정리되면서 속성 형식이 바뀌었거나(예: WM_NORMAL_HINTS의 새 필드), 국제화된 텍스트 속성을 지원하기 위해서다.

D.1 X 버전 11 호환 함수

옛 함수하던 일새 함수
XSetStandardPropertiesWM_NAME, WM_ICON_NAME, WM_HINTS, WM_COMMAND, WM_NORMAL_HINTS를 한 번에 설정XSetWMProperties
XSetNormalHints / XGetNormalHints보통 상태의 크기 힌트XSetWMNormalHints / XGetWMNormalHints
XSetZoomHints / XGetZoomHints"확대" 상태 크기 힌트ICCCM이 더 이상 지원하지 않음(대체 없음)
XSetSizeHints / XGetSizeHintsWM_SIZE_HINTS 타입의 임의 속성XSetWMSizeHints / XGetWMSizeHints
XGetStandardColormap / XSetStandardColormap표준 컬러맵 속성 하나 읽기·쓰기XGetRGBColormaps / XSetRGBColormaps
XGeometry"=80x24+10+10" 같은 위치 문자열과 기본값을 해석해 창 위치·크기 계산XWMGeometry
XGetDefault리소스 관리자의 아주 단순한 인터페이스(prog.option 한 단계만)15장의 Xrm 함수(XrmGetResource 등)
/* 옛 코드 */
XSetStandardProperties(dpy, win, "제목", "아이콘", None, argv, argc, &hints);
/* 요즘 방식 (XStringListToTextProperty 등으로 XTextProperty를 만든 뒤) */
XSetWMProperties(dpy, win, &window_name, &icon_name, argv, argc,
                 &size_hints, &wm_hints, &class_hints);

XGetDefault는 아직도 가끔 쓰인다

char *XGetDefault(Display *display, char *program, char *option);

아주 간단한 프로그램에서는 편해서 지금도 보인다. 동작을 알아 두면 좋다.

  • program에서 디렉터리 부분을 뺀 이름과 option(구성 요소 하나만)으로 prog.option을 찾는다. 클래스는 항상 "Program.Name"을 쓴다. 다단계 리소스는 쓸 수 없다.
  • 디스플레이에 XrmSetDatabase로 붙은 데이터베이스가 있으면 그것을 쓰고, 없으면 새로 만들어 붙인다(현재 로캘). 이때 내용은 0번 화면 루트 창의 RESOURCE_MANAGER 속성, 없으면 $HOME/.Xdefaults를 읽고, 그다음 XENVIRONMENT 환경 변수가 가리키는 파일(없으면 $HOME/.Xdefaults-호스트이름)을 합친다.
  • 돌려받은 문자열은 Xlib 소유다. 없으면 NULL.
char *fg = XGetDefault(dpy, argv[0], "foreground");
if (!fg) fg = "black";

D.2 X 버전 10 호환 함수 (요약)

X10 시절 코드를 옮기기 위한 함수들이다. 자주 쓰지 않아 요약만 한다.

  • 다각형·곡선 그리기: XDraw, XDrawFilled(#include <X11/X10.h>, Vertex 배열 사용). X10의 XDraw, XDrawDashed, XDrawPatterned, XDrawFilled, XDrawTiled 기능을 흉내 낸다. 서버 지원이 없고 다른 Xlib 함수를 불러 구현되므로 느리다. 직선만 그린다면 XDrawLines나 XDrawSegments가 훨씬 빠르다(채우기는 보통 XFillPolygon을 쓴다). 점선·패턴 여부는 GC 설정이 정한다. VertexDrawLastPoint, XAppendVertex, XClearVertexFlag는 지원되지 않으며, 오류 반환값의 의미가 X10과 반대(X11 관례: 실패 시 0)다.
  • 리소스 ID에 사용자 데이터 붙이기: XCreateAssocTable, XMakeAssoc, XLookUpAssoc, XDeleteAssoc, XDestroyAssocTable. 창 ID 같은 XID에 내 구조체 포인터를 연결하는 해시 표다(버킷 수는 2의 거듭제곱, 버킷당 XID 8개 이하일 때 효율적). 16장의 문맥 관리자 함수(XSaveContext, XFindContext, XDeleteContext)로 대체되었다.
/* 옛 방식 */
XAssocTable *t = XCreateAssocTable(64);
XMakeAssoc(dpy, t, win, (char *) my_data);
struct mydata *p = (struct mydata *) XLookUpAssoc(dpy, t, win);

/* 요즘 방식 (16장) */
XContext ctx = XUniqueContext();
XSaveContext(dpy, win, ctx, (XPointer) my_data);
XPointer q;
if (XFindContext(dpy, win, ctx, &q) == 0) { /* 찾음 */ }

D.3 용어집과 색인에 대하여

원문 파일에는 이 부록 뒤에 용어집(Glossary)과 색인(Index)이 이어진다. 색인은 원문 HTML의 쪽 연결용이라 번역에서는 생략한다. 용어집은 매뉴얼 전체의 용어 정의(약 130개)인데, 이 문서의 다른 장에서 이미 설명한 것이 대부분이라 X를 처음 접하는 사람이 헷갈리기 쉬운 몇 개만 짧게 옮긴다.

용어뜻
Drawable그릴 수 있는 대상. 창(window)과 픽스맵(pixmap)을 함께 이르는 말.
Atom이름 문자열에 대응하는 고유 ID. 속성 이름·타입 등에 쓴다.
Property창에 붙는 이름 있는 데이터. 창 관리자와의 통신에 쓰인다.
Grab키보드나 포인터 입력을 한 클라이언트가 독점하는 것. 능동(active)·수동(passive) 잡기가 있다.
Inferiors어떤 창의 모든 자손 창(자식, 자식의 자식...).
Viewable / VisibleViewable은 창과 모든 조상이 매핑된 상태, Visible은 실제로 화면에 보이는 부분이 있는 상태.
Escapement글자를 그린 뒤 다음 글자 원점까지의 거리(13장).
Locale / Charset / Encoding로캘은 지역화 동작 묶음, charset은 글자 집합, encoding은 글자를 바이트로 나타내는 방식(13장).
Keysym키 캡에 새겨진 기호를 나타내는 코드(KeyCode는 물리적 키 번호).
XLFDX Logical Font Description. -foundry-family-weight-... 꼴의 폰트 이름 규칙.
X Portable Character Set모든 로캘에 공통으로 있다고 가정하는 기본 글자 97개(영문자, 숫자, 기본 기호, 공백, 탭, 줄바꿈).
