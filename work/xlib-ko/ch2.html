2장. 디스플레이 함수 (Display Functions)

프로그램이 디스플레이를 쓰려면 먼저 X 서버와 연결해야 한다. 연결이 되면 이 장의 매크로와 함수로 디스플레이에 관한 정보를 얻을 수 있다. 이 장은 다음을 다룬다.

  • 디스플레이 열기(서버에 연결)
  • 디스플레이, 이미지 형식, 스크린 정보 얻기
  • NoOperation 프로토콜 요청 보내기
  • Xlib이 만든 데이터 해제
  • 디스플레이 닫기(연결 끊기)와 그때 서버가 하는 일
  • 스레드와 함께 Xlib 쓰기
  • 내부 연결(internal connection) 다루기

2.1 디스플레이 열기

Display *XOpenDisplay(char *display_name);

목적: X 서버와 연결하고, 그 연결을 나타내는 Display 구조체 포인터를 돌려준다.

display_name은 어느 디스플레이에 어떤 통신 방식으로 붙을지 정한다. POSIX 시스템에서 NULL을 넘기면 환경 변수 DISPLAY의 값을 쓴다. 이름의 해석은 구현마다 다를 수 있지만, POSIX 시스템에서는 보통 다음 형식이다.

protocol/hostname:number.screen_number
부분뜻
protocol프로토콜 계열(또는 그 별칭). 생략 가능하며, 생략하면 /도 쓰지 않는다. 지원 계열은 구현마다 다르다.
hostname디스플레이가 물리적으로 붙어 있는 컴퓨터 이름. 뒤에 콜론 하나(:) 또는 둘(::)이 온다.
number그 컴퓨터의 몇 번째 디스플레이 서버인가. 보통 0부터 센다. 뒤에 마침표(.)를 붙일 수 있다.
screen_number그 서버에서 쓸 스크린 번호. 이 값이 DefaultScreen 매크로가 돌려주는 값이 된다.

예를 들어 dual-headed:0.1은 "dual-headed라는 컴퓨터의 0번 디스플레이, 1번 스크린"이다. 흔히 보는 :0은 호스트 이름이 없으므로 "이 컴퓨터의 0번 디스플레이"이다.

통신 방식이 정해지는 규칙

  • 프로토콜이 tcp, inet, inet6이거나, 프로토콜 없이 호스트 이름과 콜론 하나가 있으면 TCP로 연결한다. inet은 IPv4, inet6은 IPv6, 그 밖에는 구현이 IP 버전을 고른다.
  • 호스트 이름과 프로토콜이 모두 없으면(:0), Xlib이 가장 빠르다고 판단하는 전송 방식(보통 로컬 IPC)을 쓴다.
  • 호스트 이름 뒤에 콜론 두 개(::)면 DECnet으로 연결한다.

서버 하나가 여러 전송 방식을 동시에 지원할 수 있고, 구현에 따라 더 많은 방식을 지원하기도 한다.

성공하면 <X11/Xlib.h>에 정의된 Display 구조체의 포인터를, 실패하면 NULL을 돌려준다. 연결에 성공하면 그 디스플레이의 모든 스크린을 쓸 수 있다. Display와 Screen 구조체의 멤버는 반드시 정보 매크로나 함수로만 읽어야 한다. 서버는 접근 제어를 할 수 있다(9.8절). 권한이 없으면 연결이 거부된다.

  • XOpenDisplay의 반환값은 반드시 NULL 검사를 한다. SSH 원격 접속에서 X 전달을 안 켰거나 DISPLAY가 비어 있으면 NULL이 온다. 검사 없이 쓰면 바로 세그폴트가 난다.
  • Display는 "연결 하나"다. 한 프로그램이 여러 서버에 붙으려면 XOpenDisplay를 여러 번 부르고, 각 연결의 리소스 ID를 섞어 쓰지 않는다.

2.2 디스플레이·이미지 형식·스크린 정보 얻기

Xlib은 Display 구조체에서 데이터를 꺼내는 매크로와, 같은 일을 하는 함수를 짝으로 제공한다. C에서는 매크로를 쓰고, 함수(이름 앞에 X가 붙은 것)는 매크로를 쓸 수 없는 다른 언어 바인딩을 위한 것이다. 매크로가 정의되지 않은 Display 멤버는 Xlib 전용이므로 직접 읽거나 고치면 안 된다.

원문이 직접 사과하는 이름 실수가 있다. XDisplayWidth, XDisplayHeight, XDisplayCells, XDisplayPlanes, XDisplayWidthMM, XDisplayHeightMM은 이름에 Display가 들어 있지만 실제로는 스크린 하나에 관한 값이다(그래서 screen_number를 받는다). 원래 Screen…이라고 불렀어야 했다.

2.2.1 디스플레이 매크로

Display와 Screen의 멤버는 읽기 전용으로 여긴다. 다만 디스플레이에 대한 다른 작업의 결과로 값이 바뀔 수는 있다. 아래 표에서 매크로와 함수는 같은 값을 돌려준다. 대부분 (display, screen_number) 또는 (display)를 받는다.

매크로 / 함수돌려주는 값
AllPlanes / unsigned long XAllPlanes(void)모든 비트가 1인 값. 함수의 plane 마스크 인자에 쓴다.
BlackPixel(display, screen_number) / XBlackPixel그 스크린의 "검정" 픽셀 값(unsigned long).
WhitePixel(display, screen_number) / XWhitePixel그 스크린의 "흰색" 픽셀 값.
ConnectionNumber(display) / XConnectionNumber연결 번호. POSIX에서는 연결의 파일 기술자(fd)다.
DefaultColormap(display, screen_number) / XDefaultColormap그 스크린의 기본 컬러맵 ID. 일상적인 색 할당은 여기서 한다.
DefaultDepth(display, screen_number) / XDefaultDepth기본 루트 창의 깊이(plane 수). 다른 깊이도 지원될 수 있다(XMatchVisualInfo).
DefaultGC(display, screen_number) / XDefaultGC그 스크린 루트 창용 기본 GC. 전경=검정, 배경=흰색으로 초기화돼 있다.
DefaultRootWindow(display) / XDefaultRootWindow기본 스크린의 루트 창.

DisplayCells(display, screen_number) / XDisplayCells기본 컬러맵의 항목 수.

NextRequest(display) / XNextRequest다음 요청에 쓰일 일련번호. 일련번호는 연결마다 따로 관리된다.
ProtocolVersion(display) / XProtocolVersionX 프로토콜 주 버전(11).
ProtocolRevision(display) / XProtocolRevision서버의 부 프로토콜 개정 번호.

몇 가지는 따로 설명이 필요하다.

BlackPixel/WhitePixel: 흑백 응용을 만들 때 쓰는 값이다. 기본 컬러맵에 영구적으로 할당된 항목의 픽셀 값이다. 일부 스크린에서는 실제 RGB를 바꿀 수 있고, 어쨌든 진짜 검정·흰색이 아닐 수도 있다. 이름은 "상대적으로 어두운 색/밝은 색"이라는 뜻으로 받아들인다. 또 이것은 픽셀 값이지 RGB 값이 아니다. 0이 검정이라고 가정하면 안 된다.

DefaultGC: 간단한 응용의 편의를 위해 만들어 둔 GC다. Xlib 함수 내부에서 쓰지 않으므로 내용을 자유롭게 바꿔도 된다. 하지만 절대 해제(XFreeGC)하면 안 된다.

DisplayString: fork한 자식 프로세스가 같은 디스플레이에 새 연결을 열 때나 오류 메시지를 출력할 때 쓸모 있다. (부모와 자식이 같은 Display *를 함께 쓰면 연결 스트림이 꼬이므로 자식은 새로 연결하는 것이 맞다.)

int *XListDepths(Display *display, int screen_number, int *count_return);

목적: 그 스크린에서 쓸 수 있는 깊이들의 배열을 돌려준다. 스크린 번호가 올바르고 메모리를 할당할 수 있으면 count_return에 개수를 넣는다. 아니면 count_return을 건드리지 않고 NULL을 돌려준다. 배열은 XFree로 해제한다.

long XMaxRequestSize(Display *display);
long XExtendedMaxRequestSize(Display *display);

목적: 서버가 받을 수 있는 요청 하나의 최대 크기(4바이트 단위)를 알려 준다.

  • XMaxRequestSize는 확장 길이 인코딩 없이 받을 수 있는 최대치다. 프로토콜은 최소 4096단위(16384바이트)를 보장한다. XDrawPoints, XDrawRectangles, XDrawSegments, XFillArcs, XFillRectangles, XPutImage는 Xlib이 필요하면 자동으로 여러 요청으로 나눈다.
  • XExtendedMaxRequestSize는 서버가 확장 길이(extended-length) 인코딩을 지원하지 않으면 0, 지원하면 그 최대치를 돌려준다. XDrawLines, XDrawArcs, XFillPolygon, XChangeProperty, XSetClipRectangles, XSetRegion은 지원되면 필요할 때 확장 인코딩을 쓴다. 위의 자동 분할 함수들은 확장 인코딩을 써도 되고 나눠 보내도 된다(구현 선택).
XDrawLines나 XFillPolygon처럼 "이어진 하나의 도형"은 나눠 보내면 모양이 달라지므로 자동 분할 대상이 아니다. 아주 많은 점을 넘길 때는 이 한계를 넘지 않는지 확인한다.
/* 연결 정보를 출력하는 예 -- cc info.c -lX11 */
#include <stdio.h>
#include <X11/Xlib.h>

int main(void)
{
    Display *dpy = XOpenDisplay(NULL);
    int s, n, i, *depths;

    if (!dpy) { fprintf(stderr, "no display\n"); return 1; }
    s = DefaultScreen(dpy);
    printf("display  : %s\n", DisplayString(dpy));
    printf("vendor   : %s (release %d)\n", ServerVendor(dpy), VendorRelease(dpy));
    printf("protocol : X%d.%d\n", ProtocolVersion(dpy), ProtocolRevision(dpy));
    printf("screens  : %d (default %d)\n", ScreenCount(dpy), s);
    printf("size     : %dx%d px, %dx%d mm\n",
           DisplayWidth(dpy, s), DisplayHeight(dpy, s),
           DisplayWidthMM(dpy, s), DisplayHeightMM(dpy, s));
    printf("depth    : %d\n", DefaultDepth(dpy, s));

    depths = XListDepths(dpy, s, &n);
    if (depths) {
        printf("depths   :");
        for (i = 0; i < n; i++) printf(" %d", depths[i]);
        printf("\n");
        XFree(depths);
    }
    printf("max req  : %ld units\n", XMaxRequestSize(dpy));
    XCloseDisplay(dpy);
    return 0;
}

2.2.2 이미지 형식 함수와 매크로

응용은 서버가 요구하는 형식으로 이미지 데이터를 보내야 한다. 변환 작업 대부분은 Xlib이 대신 해 준다(8.7절, 16.8절). 직접 이미지 바이트를 다룰 때만 아래 정보가 필요하다.

typedef struct {
    int depth;
    int bits_per_pixel;
    int scanline_pad;
} XPixmapFormatValues;

XPixmapFormatValues *XListPixmapFormats(Display *display, int *count_return);

목적: 연결 설정 때 서버가 알려 준 Z 형식 이미지의 형식 목록을 돌려준다. 깊이마다 픽셀당 비트 수(bits_per_pixel)와 스캔라인 패딩(scanline_pad)이 있다. 예를 들어 깊이 24인데 bits_per_pixel이 32인 경우가 흔하다. 메모리가 부족하면 NULL. 결과는 XFree로 해제한다.

매크로 / 함수돌려주는 값
ImageByteOrder(display) / XImageByteOrder이미지 바이트 순서: XY 형식(bitmap)에서는 스캔라인 단위마다, Z 형식에서는 픽셀 값마다. LSBFirst 또는 MSBFirst.
BitmapUnit(display) / XBitmapUnitbitmap 스캔라인 단위 크기(비트). 스캔라인은 이 값의 배수로 계산된다.
BitmapBitOrder(display) / XBitmapBitOrder각 단위 안에서 화면상 가장 왼쪽 비트가 최하위 비트인지 최상위 비트인지. LSBFirst 또는 MSBFirst.
BitmapPad(display) / XBitmapPad각 스캔라인이 맞춰져야 하는 비트 배수.
DisplayHeight / XDisplayHeight (display, screen_number)스크린 높이(픽셀).
DisplayHeightMM / XDisplayHeightMM스크린 높이(mm).
DisplayWidth / XDisplayWidth스크린 너비(픽셀).
DisplayWidthMM / XDisplayWidthMM스크린 너비(mm).

픽셀 수와 mm 값을 함께 쓰면 DPI(인치당 점 수)를 계산할 수 있다: DisplayWidth * 25.4 / DisplayWidthMM. 다만 서버가 알려 주는 mm 값이 정확하지 않은 경우도 있다.

2.3 NoOperation 요청 보내기

XNoOp(Display *display);

목적: 아무 일도 하지 않는 NoOperation 프로토콜 요청을 서버에 보내 연결을 "운동"시킨다. 자주 쓰지 않아 요약만 한다. 요청도 버퍼에 들어가므로 실제로 보내려면 flush가 필요하다.

2.4 Xlib이 만든 데이터 해제

XFree(void *data);

목적: Xlib이 할당해 돌려준 메모리를 해제하는 범용 함수다. 객체마다 전용 해제 함수가 명시돼 있지 않다면 Xlib이 할당한 것은 모두 XFree로 해제해야 한다(XListDepths, XListPixmapFormats의 결과 등).

  • XFree에 NULL을 넘기면 안 된다. 표준 free(NULL)과 다르다. 반환값을 확인한 뒤 해제한다.
  • Xlib이 준 메모리를 free로 풀거나, 내가 malloc한 메모리를 XFree로 풀지 않는다. 실제 구현이 같아 보여도 규약상 짝을 맞춘다.
  • XFontStruct처럼 전용 해제 함수(XFreeFontInfo 등)가 있는 객체는 그것을 쓴다.

2.5 디스플레이 닫기

XCloseDisplay(Display *display);

목적: 서버와의 연결을 닫는다. 이때 클라이언트가 이 디스플레이에 만든 모든 창과 리소스 ID(Window, Font, Pixmap, Colormap, Cursor, GContext) 및 기타 리소스가 파괴된다(close-down 모드를 바꾸지 않았다면). 그러니 닫은 뒤 그것들을 다시 참조하면 안 된다.

프로그램이 끝나기 전에 XCloseDisplay를 명시적으로 부르는 것이 좋다. 마지막에 XSync를 수행하므로 아직 보고되지 않은 오류가 보고되기 때문이다. 그냥 exit하면 버퍼에 남은 요청과 그 오류가 사라질 수 있다. XCloseDisplay는 BadGC 오류를 낼 수 있다.

XSetCloseDownMode(Display *display, int close_mode);

목적: 연결이 닫힐 때 내 리소스를 어떻게 할지 정한다. 연결은 처음에 DestroyAll 모드다.

  • close_mode: DestroyAll, RetainPermanent, RetainTemporary 중 하나. 다른 값이면 BadValue.

Retain 계열을 쓰면 클라이언트가 끝난 뒤에도 리소스(예: 루트 창 배경으로 쓰는 pixmap)가 서버에 남는다. 자세한 동작은 다음 절이다.

2.6 서버 연결이 닫힐 때 일어나는 일

XCloseDisplay를 부르든 프로세스가 그냥 끝나든, 서버는 연결이 닫히면 자동으로 다음을 한다.

  • 그 클라이언트가 가진 모든 selection의 소유를 포기한다(XSetSelectionOwner 참고).
  • 포인터나 키보드를 능동적으로 grab하고 있었다면 XUngrabPointer, XUngrabKeyboard를 한다.
  • 서버를 grab하고 있었다면 XUngrabServer를 한다.
  • 그 클라이언트의 모든 수동(passive) grab을 해제한다.
  • close-down 모드가 RetainPermanent나 RetainTemporary면, 클라이언트가 할당한 모든 리소스(컬러맵 항목 포함)를 영구 또는 임시로 표시한다. 그래도 다른 클라이언트가 명시적으로 파괴하는 것까지 막지는 않는다(XKillClient로 지울 수 있다).

close-down 모드가 DestroyAll이면 서버는 리소스를 다음처럼 파괴한다.

  • save-set 처리: save-set은 "다른 클라이언트의 창" 목록이다(주로 창 관리자가 씀). 각 save-set 창이 이 클라이언트가 만든 창의 하위 창이면, 그 창을 가장 가까운 (이 클라이언트 것이 아닌) 조상으로 reparent한다. 루트 기준 바깥 왼쪽 위 모서리의 절대 좌표는 그대로 유지된다. 그리고 save-set 창이 unmap돼 있으면 MapWindow를 수행한다(하위 창이 아니었더라도). 덕분에 창 관리자가 죽어도 그 프레임 안에 있던 응용 창들이 사라지지 않고 루트로 돌아온다.
  • 이 클라이언트가 만든 모든 창을 파괴한다.
  • 창이 아닌 리소스(Font, Pixmap, Cursor, Colormap, GContext)마다 해당 해제 요청을 수행한다.
  • 할당한 모든 색과 컬러맵 항목을 해제한다.

서버는 "연결 없음"과 "연결 있음" 상태를 오간다. DestroyAll 모드의 연결이 닫혀 마지막 연결이 사라지면, 서버는 막 시작한 것처럼 상태를 리셋한다.

  • RetainPermanent/RetainTemporary로 끝난 클라이언트들이 남긴 리소스를 모두 파괴한다.
  • 미리 정의된 것 외의 모든 아톰을 지운다.
  • 모든 루트 창의 모든 속성(property)을 지운다(4.3절).
  • 모든 장치 맵과 속성(키 클릭, 벨 볼륨, 가속 등)과 접근 제어 목록을 리셋한다.
  • 표준 루트 타일과 커서를 복구한다.
  • 기본 글꼴 경로를 복구한다.
  • 입력 포커스를 PointerRoot로 되돌린다.

단, 마지막 연결이 RetainPermanent나 RetainTemporary 모드로 닫혔다면 서버는 리셋하지 않는다.

grab을 건 채로 프로그램이 멈추면(무한 루프 등) 화면 전체가 입력을 받지 않는 것처럼 보인다. 프로세스를 죽이면 연결이 닫히면서 서버가 grab을 자동으로 풀어 준다.

2.7 스레드와 함께 Xlib 쓰기

스레드가 있는 시스템에서는 여러 스레드가 Xlib을 동시에 쓸 수 있도록 지원할 수 있다.

Status XInitThreads(void);

목적: Xlib의 동시 스레드 지원을 초기화한다.

  • 멀티스레드 프로그램이 부르는 첫 번째 Xlib 함수여야 하고, 다른 어떤 Xlib 호출보다 먼저 끝나야 한다. XOpenDisplay보다도 먼저다.
  • 성공하면 0이 아닌 값, 실패하면 0. 스레드를 지원하지 않는 시스템에서는 항상 0.
  • 여러 스레드가 Xlib을 동시에 쓸 수 있을 때만 필요하다. 툴킷의 뮤텍스나 직접 만든 잠금으로 모든 Xlib 호출을 보호한다면 필요 없다.
  • 단일 스레드 프로그램은 부르지 않는 것이 권장된다(잠금 비용이 생긴다).
XLockDisplay(Display *display);
XUnlockDisplay(Display *display);

목적: 여러 Xlib 호출을 하나로 묶어, 그 동안 다른 스레드가 같은 디스플레이를 쓰지 못하게 한다. 다른 스레드는 잠금이 풀릴 때까지 블록된다. 중첩 호출이 올바르게 동작하므로, XLockDisplay를 부른 횟수만큼 XUnlockDisplay를 불러야 실제로 풀린다. XInitThreads가 성공하지 않았다면 둘 다 아무 효과가 없다.

/* cc thr.c -lX11 -lpthread */
#include <X11/Xlib.h>

int main(void)
{
    Display *dpy;
    if (!XInitThreads())          /* 반드시 맨 처음 */
        return 1;
    dpy = XOpenDisplay(NULL);
    if (!dpy) return 1;

    /* ... 여러 스레드를 만든다 ... */

    /* 어떤 스레드에서: 두 호출 사이에 다른 스레드가 끼어들지 않게 */
    XLockDisplay(dpy);
    /* XMoveWindow(...); XRaiseWindow(...); 등 */
    XUnlockDisplay(dpy);

    XCloseDisplay(dpy);
    return 0;
}
XInitThreads를 늦게(이미 XOpenDisplay를 한 뒤에) 부르는 것은 흔한 실수이며, 이후 동작은 보장되지 않는다. 또 한 스레드가 XNextEvent에서 기다리는 동안 다른 스레드가 같은 디스플레이를 쓰는 구조는 설계가 까다롭다. 가능하면 Xlib 호출을 한 스레드에 모으는 편이 단순하다.

2.8 내부 연결 사용

Xlib 구현은 X 서버 연결 외에 다른 서버(예: 13장의 입력 메서드 서버)와 연결이 필요할 수 있다. 여러 디스플레이를 쓰거나 디스플레이와 다른 입력(소켓, 파이프 등)을 함께 select/poll로 기다리는 툴킷·클라이언트는 이런 추가 연결도 알아야 제대로 블록하고 입력을 처리할 수 있다. 디스플레이 하나만 쓰고 Xlib 이벤트 함수에서 기다리는 단순한 클라이언트는 이 기능이 필요 없다.

typedef void (*XConnectionWatchProc)(Display *display, XPointer client_data,
                                     int fd, Bool opening, XPointer *watch_data);

Status XAddConnectionWatch(Display *display, XConnectionWatchProc procedure,
                           XPointer client_data);

목적: Xlib이 그 디스플레이용 내부 연결을 열거나 닫을 때마다 불릴 콜백을 등록한다.

  • 콜백은 display, 등록 때 준 client_data, 연결의 fd, 여는 중인지(opening), 그리고 개인 데이터를 둘 자리(watch_data)를 받는다. opening이 True일 때 *watch_data에 포인터를 저장해 두면, 같은 연결이 닫힐 때(opening이 False) 그 포인터가 그대로 들어 있다.
  • 디스플레이를 연 뒤 언제든 부를 수 있다. 이미 내부 연결이 있으면, 반환하기 전에 각각에 대해 콜백이 즉시 불린다.
  • 등록 성공 시 0이 아닌 값, 실패 시 0.
콜백 안에서는 Xlib 함수를 부르면 안 된다. 콜백이 직간접으로 내부 연결이나 watch 상태를 바꾸면 결과가 정의되지 않는다. 스레드 초기화가 돼 있으면 콜백은 디스플레이가 잠긴 상태로 불리므로, 그 스레드가 미리 XLockDisplay로 바깥에서 잠그지 않았다면 디스플레이를 잠그는 Xlib 함수 호출 결과는 정의되지 않는다. 콜백에서는 fd를 내 select 집합에 넣고 빼는 일만 한다.
Status XRemoveConnectionWatch(Display *display, XConnectionWatchProc procedure,
                              XPointer client_data);

목적: 등록한 콜백을 제거한다. client_data가 등록 때와 같아야 한다.

void XProcessInternalConnection(Display *display, int fd);

목적: 내부 연결에 도착한 입력을 처리한다. select나 poll이 그 fd에 입력이 있다고 알려 준 뒤에만 불러야 한다. 아니면 결과가 정의되지 않는다.

Status XInternalConnectionNumbers(Display *display, int **fd_return, int *count_return);

목적: 현재 열려 있는 모든 내부 연결의 fd 목록을 돌려준다. 목록은 다 쓰면 XFree로 해제한다. 목록 할당에 성공하면 0이 아닌 값, 아니면 0.

/* X 연결과 표준 입력을 함께 기다리는 골격 (내부 연결은 생략) */
#include <sys/select.h>
#include <unistd.h>
#include <X11/Xlib.h>

void loop(Display *dpy)
{
    int xfd = ConnectionNumber(dpy);
    XEvent ev;
    for (;;) {
        fd_set rfds;
        XFlush(dpy);                       /* 기다리기 전에 요청을 내보낸다 */
        while (XPending(dpy)) {            /* 이미 읽힌 이벤트 먼저 처리 */
            XNextEvent(dpy, &ev);
            /* ... 이벤트 처리 ... */
        }
        FD_ZERO(&rfds);
        FD_SET(xfd, &rfds);
        FD_SET(STDIN_FILENO, &rfds);
        if (select(xfd + 1, &rfds, NULL, NULL, NULL) < 0)
            break;
        if (FD_ISSET(STDIN_FILENO, &rfds)) {
            /* ... 표준 입력 처리 ... */
        }
    }
}
ConnectionNumber의 fd만 select하면 함정이 있다. Xlib이 이미 소켓에서 읽어 큐에 넣어 둔 이벤트는 fd에 더 이상 "읽을 것"으로 나타나지 않는다. 그래서 select 전에 XPending으로 큐를 비우는 것이 중요하다.
