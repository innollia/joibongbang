13장. 로캘과 국제화 텍스트 함수 (Locales and Internationalized Text Functions)

이 장은 "한글·일본어·중국어처럼 ASCII 밖의 글자를 X 프로그램에서 어떻게 그리고, 어떻게 입력받는가"를 다룬다. 원문은 아주 길지만 핵심 흐름은 단순하다.

  1. setlocale로 로캘을 정하고, XSupportsLocale로 Xlib이 그 로캘을 지원하는지 확인하고, XSetLocaleModifiers로 입력기 같은 수식자를 정한다.
  2. 글자를 그릴 때는 폰트 하나(XFontStruct) 대신 폰트 세트(XFontSet)를 만들어 XmbDrawString 같은 함수로 그린다. 이것이 출력 방법(XOM)이다.
  3. 글자를 입력받을 때는 입력 방법(XIM)을 열고 입력 문맥(XIC)을 만든 뒤, 이벤트마다 XFilterEvent를 거치고 XmbLookupString으로 완성된 문자열을 받는다.

용어부터 정리한다. 국제화(internationalization)는 프로그램 소스를 고치거나 다시 컴파일하지 않고도 여러 언어·관습·문자 인코딩에 맞출 수 있게 만드는 일이고, 실제로 특정 언어에 맞추는 것을 지역화(localization)라고 한다. 그 기준이 되는 것이 로캘(locale)이다. 로캘은 Xlib의 다음 동작에 영향을 준다.

  • 입력기가 돌려주는 텍스트의 인코딩과 처리
  • 리소스 파일과 리소스 값의 인코딩
  • 텍스트 문자열의 인코딩과 그리기
  • 클라이언트끼리 주고받는 텍스트(속성 등)의 인코딩·디코딩

이 장의 함수들은 멀티바이트(char *, 이름에 Xmb)판과 와이드 문자(wchar_t *, 이름에 Xwc)판이 짝을 이룬다. 두 판은 텍스트 인자의 형태만 다르고 기능은 같다. 또 원문은 이 기능이 "한 문장 안에 여러 언어를 섞는 다국어 프로그램"을 위한 것은 아니며, 서로 독립된 문맥에서 여러 언어를 제한적으로 쓰는 정도를 가능하게 한다고 분명히 적는다.

Xutf8 함수에 대하여: 이 매뉴얼 본문에는 Xutf8DrawString, Xutf8LookupString 같은 Xutf8 계열이 나오지 않는다. 이 함수들은 나중에(XFree86 시절) libX11에 추가된 확장으로, <X11/Xlib.h>에 X_HAVE_UTF8_STRING 매크로가 정의돼 있으면 쓸 수 있다. 인자와 동작은 대응하는 Xmb 함수와 똑같고, 다만 문자열이 현재 로캘의 인코딩이 아니라 항상 UTF-8이라는 점만 다르다. 오늘날 리눅스는 대부분 UTF-8 로캘이라 Xmb와 Xutf8의 결과가 같지만, 프로그램 내부 문자열이 UTF-8로 고정돼 있다면 Xutf8판을 쓰는 편이 안전하다. 아래 예제에서는 이 두 계열을 함께 보여 준다.

13.1 X 로캘 관리 (X Locale Management)

ANSI C 라이브러리를 따르는 시스템에서는 로캘을 정하는 방법이 setlocale이다. 이 호출 하나가 C 라이브러리와 Xlib 양쪽의 로캘을 함께 정한다. Xlib의 동작을 좌우하는 것은 그중 LC_CTYPE 범주이며, 이를 현재 로캘(current locale)이라고 부른다.

그런데 X가 호스트가 지원하는 모든 로캘을 지원해야 하는 것은 아니다. 그래서 확인 함수가 있다.

Bool XSupportsLocale(void);

목적: 현재 로캘에서 Xlib 함수들이 제대로 동작할 수 있는지 알려 준다.

  • True면 지원. False면, 반환값으로 XLocaleNotSupported가 정의된 로캘 의존 함수들은 그 값을 돌려주고, 나머지 로캘 의존 함수들은 "C" 로캘로 동작한다.

로캘과 X 수식자를 고르는 책임은 클라이언트에게 있다. 대부분의 클라이언트는 다음 세 함수를 차례로 부른다: 호스트의 로캘 설정 함수(setlocale), XSupportsLocale, XSetLocaleModifiers.

char *XSetLocaleModifiers(char *modifier_list);

목적: 현재 로캘에 대한 X 수식자(modifier)를 설정한다.

  • modifier_list: "@category=value" 꼴을 0개 이상 이어 붙인 문자열. 현재 표준으로 정해진 범주는 im(입력 방법 선택) 하나뿐이고, 그 값(입력기 이름)은 표준화돼 있지 않다. 예: "@im=ibus", "@im=fcitx".
  • 호스트의 기본 수식자(POSIX 시스템에서는 환경 변수 XMODIFIERS)가 이 목록 뒤에 덧붙여진다. 같은 범주가 여러 번 나오면 앞의 것이 이긴다. 그래서 XSetLocaleModifiers("")를 부르면 사용자의 XMODIFIERS가 그대로 적용된다.
  • 범주가 목록에 아예 없거나 값이 빈 문자열이면 구현이 정한 기본값이 쓰인다.
  • 성공하면 "같은 로캘에서 이 문자열로 다시 부르면 지금 설정이 복원되는" 문자열을 돌려준다. NULL을 넘기면 설정은 바꾸지 않고 현재 설정 문자열만 돌려준다. 잘못된 값이 있으면 NULL을 돌려주고 아무것도 바꾸지 않는다.
  • 돌려받은 문자열은 Xlib 소유다. 고치거나 해제하지 않는다.
주의: 프로그램 시작 직후나 로캘을 바꾼 직후에는 수식자 값이 "정해지지 않은" 상태다. 그래서 로캘을 정한 다음, 로캘 의존 Xlib 함수를 부르기 전에 반드시 NULL이 아닌 인자로 XSetLocaleModifiers를 불러야 한다. 이 호출을 빠뜨리면 XOpenIM이 엉뚱한 입력기를 찾거나 실패하는 일이 흔하다.

원문이 권하는 로캘·수식자 값의 우선순위는 ① 명령행 옵션 ② 리소스 ③ 빈 문자열("", 즉 환경 변수에 맡김) 순이다. 명령행이나 리소스로 로캘을 지정했다면 모든 범주를 그 로캘로 맞추는 것이 좋다.

예제: 로캘 초기화의 정석

#include <locale.h>
#include <stdio.h>
#include <X11/Xlib.h>

int init_locale(void)
{
    if (setlocale(LC_ALL, "") == NULL)      /* LANG, LC_ALL 등 환경 변수를 따른다 */
        fprintf(stderr, "setlocale 실패, C 로캘로 진행\n");
    if (!XSupportsLocale()) {
        fprintf(stderr, "X가 이 로캘을 지원하지 않음\n");
        setlocale(LC_ALL, "C");
    }
    if (XSetLocaleModifiers("") == NULL)    /* XMODIFIERS 적용 */
        fprintf(stderr, "XSetLocaleModifiers 실패\n");
    return 0;
}
setlocale(LC_ALL, "")를 부르지 않으면 C 프로그램은 항상 "C" 로캘로 시작한다. 이 상태에서는 한글이 들어간 UTF-8 문자열을 XmbDrawString에 넘겨도 제대로 나오지 않는다. 한글이 깨지면 가장 먼저 이 호출과 LANG=ko_KR.UTF-8 같은 환경 변수를 확인한다.

13.2 로캘과 수식자 의존성 (Locale and Modifier Dependencies)

국제화 Xlib 함수들은 두 가지 중 하나의 로캘을 따른다: 호출 시점의 현재 로캘, 또는 함수에 넘긴 객체가 만들어질 때의 로캘. 원문 표를 요약하면 다음과 같다.

로캘을 정하는 것영향을 받는 함수무엇에 영향
setlocaleXSupportsLocale, XSetLocaleModifiers로캘 조회·수식자 설정
setlocaleXrmGetFileDatabase, XrmGetStringDatabase만들어지는 XrmDatabase의 로캘
XrmDatabaseXrmPutFileDatabase, XrmLocaleOfDatabase데이터베이스의 로캘
setlocaleXmbSetWMProperties, XmbTextPropertyToTextList, XwcTextListToTextProperty 등주고받는 텍스트의 인코딩
setlocaleXOpenIM, XRegisterIMInstantiateCallback어떤 입력 방법을 고를지
XIMXCreateIC, XLocaleOfIM입력 문맥 설정

setlocaleXOpenOM, XCreateFontSet출력 방법, 폰트 세트의 문자 집합
XFontSet/XOCXmbDrawText, XmbTextExtents, XExtentsOfFontSet 등넘기는 텍스트의 로캘, 로캘 의존 크기 정보

왜 이런 구분이 필요할까? 예를 들어 폰트 세트를 만든 뒤에 setlocale로 로캘을 바꿔도, 그 폰트 세트로 그리는 글자는 만들 때의 로캘로 해석된다. 객체가 로캘을 "붙잡고" 있기 때문이다. 따라서 로캘을 바꾸려면 관련 객체(폰트 세트, 입력 방법)를 새로 만들어야 한다.

그 밖의 규칙:

  • 로캘이 같으면, X 함수가 돌려준 로캘 인코딩 문자열을 C 라이브러리 함수에 넘겨도 되고 그 반대도 된다.
  • 상태 의존(state-dependent) 인코딩이라면 모든 문자열은 그 인코딩의 초기 상태에서 시작한다고 가정한다.
  • Xlib 함수는 현재 로캘이나 X 수식자를 바꾸지 않는 것처럼 동작한다(내부에서 바꾸더라도 저장했다가 되돌린다). 또 mblen, mbtowc, wctomb, strtok의 전역 상태도 건드리지 않는다.

13.3 가변 인자 목록 (Variable Argument Lists)

이 장의 함수 중 ...가 있는 것(XCreateIC, XSetICValues, XGetIMValues 등)은 이름-값 쌍의 목록을 받는다. 이름은 문자열(XNInputStyle 같은 상수), 값은 XPointer 크기의 값이며, 이름 자리에 NULL이 오면 목록이 끝난다.

목록 안에 또 다른 목록을 넣을 수도 있다. 이름 자리에 XNVaNestedList를 쓰면 다음 값이 XVaNestedList로 해석되어 그 자리에 "펼쳐서" 끼워진다. 미리보기(preedit)·상태(status) 속성은 반드시 이 중첩 목록으로 넘겨야 하므로 실제로 자주 쓴다.

XVaNestedList XVaCreateNestedList(int dummy, ...);

목적: 이름-값 쌍들을 하나의 중첩 목록 포인터로 묶는다.

  • dummy: 쓰지 않는 인자. ANSI C의 가변 인자 함수는 고정 인자가 하나 이상 있어야 해서 존재한다. 보통 0을 넘긴다.
  • 항목은 그대로 복사되지만, 포인터가 가리키는 데이터는 복사되지 않는다. 목록을 쓰는 동안 그 데이터가 살아 있어야 한다.
  • 다 쓰면 XFree로 해제한다.
XPoint spot = { 10, 20 };
XVaNestedList attr = XVaCreateNestedList(0, XNSpotLocation, &spot, NULL);
XSetICValues(ic, XNPreeditAttributes, attr, NULL);
XFree(attr);
원문의 함수 원형 표기는 XVaCreateNestedList(int dummy)처럼 ...가 빠져 보이는데(문서 변환 과정의 누락), 실제로는 가변 인자 함수다. XSetOMValues, XCreateIC 등 이 장의 다른 원형도 마찬가지로 끝의 ...가 빠져 있다.

13.4 출력 방법 (Output Methods)

13.4.1 개요

로캘에 따라 텍스트 하나가 여러 "구성 요소"로 나뉘고, 요소마다 다른 폰트와 문자 집합(charset)이 필요할 수 있다. 예컨대 옛 EUC-KR 로캘에서 "Hello 안녕"을 그리려면 영문은 ISO8859-1 폰트, 한글은 KSC5601 폰트가 필요했다. 언어에 따라 쓰는 방향이 다르거나(아랍어·히브리어), 이웃 글자에 따라 모양이 바뀌는(문맥 의존) 경우도 있다.

이런 로캘별 지식을 클라이언트가 일일이 알 필요 없도록 해 주는 것이 X 출력 방법(XOM)이다. 출력 방법이 해 주는 일은 네 가지다.

  • 로캘 텍스트를 그리는 데 필요한 폰트들의 집합을 만든다.
  • 폰트 세트로 텍스트를 그린다(호출자는 로캘 세부를 몰라도 된다).
  • 텍스트의 진행 거리(escapement)와 크기(extents)를 픽셀 단위로 알려 준다.
  • 양방향이나 문맥 의존 그리기가 필요한지 알려 준다.

추상화는 둘이다. 출력 방법 자체는 XOM, 특정 출력 "흐름"의 상태는 출력 문맥 XOC다. XOC는 XFontSet과 같은 타입처럼 쓸 수 있으며(호환), 더 일반화된 개념이다. 대부분의 프로그램은 XOM/XOC를 직접 다루지 않고 편의 함수 XCreateFontSet만 쓴다.

13.4.2 출력 방법 함수

XOM XOpenOM(Display *display, XrmDatabase db, char *res_name, char *res_class);
Status XCloseOM(XOM om);
char *XSetOMValues(XOM om, ...);
char *XGetOMValues(XOM om, ...);
Display *XDisplayOfOM(XOM om);
char *XLocaleOfOM(XOM om);
  • XOpenOM: 현재 로캘과 수식자에 맞는 출력 방법을 연다. 로캘은 여는 순간 고정되며 나중에 바꿀 수 없다. db는 출력 방법이 자기 전용 리소스를 찾을 데이터베이스(NULL 가능), res_name/res_class는 그때 접두어로 쓸 응용의 이름·클래스다. 이 두 문자열은 호출 뒤에 버려도 되지만 db는 출력 방법이 살아 있는 동안 유지해야 한다. 실패하면 NULL.
  • XSetOMValues/XGetOMValues: 성공하면 NULL, 실패하면 처리하지 못한 첫 인자의 이름을 돌려준다. Xlib이 정한 "설정 가능한" 표준 OM 값은 없고, 읽기 전용 값만 있다.

읽을 수 있는 XOM 값:

XOM 값뜻
XNRequiredCharSet이 로캘에 필요한 charset 목록(XOMCharSetList: charset_count, charset_list). Xlib 소유, XCloseOM 때 해제.
XNQueryOrientation지원하는 전체 글 방향 목록(XOMOrientation). XOMOrientation_LTR_TTB(왼→오, 위→아래)는 항상 있고 나머지(RTL_TTB, TTB_LTR, TTB_RTL, Context)는 로캘에 따라 다르다. 클라이언트가 XFree로 해제.
XNDirectionalDependentDrawingTrue면 그리기 함수가 방향성 텍스트를 알아서 재배열한다. False면 모두 왼→오로 가정.
XNContextualDrawingTrue면 문맥에 따른 글자 모양 변경·글리프 결합을 해 준다.

                        int *missing_charset_count_return,
                        char **def_string_return);

목적: 현재 로캘에 필요한 폰트들을 모아 폰트 세트를 만든다. 내부적으로 출력 방법을 몰래 열고(XNOMAutomatic=True) 기본값으로 출력 문맥을 만드는 편의 함수다.

  • base_font_name_list: 쉼표로 구분한 기본 폰트 이름들. 쉼표 양옆 공백은 무시된다. XLFD 이름을 쓰면 charset 부분을 생략하거나 *로 두어, 하나의 이름으로 여러 로캘에 필요한 폰트를 모두 찾게 할 수 있다. XLFD가 아닌 이름(별칭)을 주면 Xlib이 폰트 속성에서 XLFD 이름을 알아내려 시도한다.
  • missing_charset_list_return/missing_charset_count_return: 폰트를 찾지 못한 charset 목록과 개수. 다 찾았으면 NULL과 0. 목록은 XFreeStringList로 해제한다.
  • def_string_return: 빠진 charset의 글자 대신 그려질 문자열. 빈 문자열이면 아무것도 그리지 않고 진행 거리도 0이다. Xlib 소유이므로 해제하지 않는다.

Xlib은 로캘이 요구하는 charset마다 기본 이름 목록을 앞에서부터 훑어, 대략 다음 순서로 처음 맞는 것을 고른다: ① 그 charset(또는 그 상위 집합, 예: ASCII 대신 ISO8859-1)을 명시한 XLFD 이름 ② 그 charset으로 다시 매핑할 수 있는 charset을 명시한 이름들 ③ 첫 XLFD 이름의 charset 필드를 필요한 charset으로 바꿔 끼운 이름 ④ 구현 나름대로 매핑할 수 있는 이름.

그래서 다음 세 방식이 모두 가능하다.

/* 1) charset까지 정확히 지정 */
"-JIS-Fixed-Medium-R-Normal--26-180-100-100-C-240-JISX0208.1983-0,"
"-Adobe-Courier-Bold-R-Normal--25-180-75-75-M-150-ISO8859-1"
/* 2) charset만 빼고 지정 */
"-JIS-Fixed-Medium-R-Normal--26-180-100-100-C-240,"
"-Adobe-Courier-Bold-R-Normal--25-180-100-100-M-150"
/* 3) 조건만 주고 Xlib에 맡김 */
"-*-*-*-R-Normal--*-180-100-100-*-*"

반환값 규칙: 메모리 부족이나 로캘 미지원이면 NULL. 필요한 charset 중 하나도 폰트가 없거나, 로캘 정의상 꼭 있어야 하는 charset의 폰트가 없으면 역시 NULL. 일부만 빠졌으면 유효한 폰트 세트를 돌려주면서 빠진 목록을 알려 준다. 즉 "NULL이 아니다 = 모든 글자가 나온다"가 아니다. 무엇을 경고할지는 클라이언트가 정한다.

int  XFontsOfFontSet(XFontSet font_set, XFontStruct ***font_struct_list_return,
                     char ***font_name_list_return);
char *XBaseFontNameListOfFontSet(XFontSet font_set);
char *XLocaleOfFontSet(XFontSet font_set);
void  XFreeFontSet(Display *display, XFontSet font_set);
  • XFontsOfFontSet: 실제 쓰인 XFontStruct 목록과 폰트 이름 목록을 돌려주고, 개수를 반환한다. 둘 다 Xlib 소유다. 폰트 데이터가 미리 다 읽혀 있다는 보장이 없어서 per_char 정보는 있을 수도 없을 수도 있다.
  • XBaseFontNameListOfFontSet: 만들 때 준 기본 이름 목록(XLFD로 바뀌었으면 바뀐 이름).
  • XLocaleOfFontSet: 폰트 세트에 묶인 로캘 이름.
  • XFreeFontSet: 폰트 세트와 거기 딸린 이름 목록, XFontStruct 목록, XFontSetExtents를 해제한다. XCreateFontSet으로 만든 것이면 몰래 연 XOM도 닫는다.

13.4.5 폰트 세트 크기 정보 (Obtaining Font Set Metrics)

몇 가지 개념을 먼저 잡는다. 주 진행 방향(primary draw direction)은 글자가 이어지며 원점이 나아가는 방향인데, 현재 Xlib 인터페이스는 왼→오만 정의한다. 그리기 원점은 그리기 함수에 넘긴 (x, y)이고, 기준선(baseline)은 원점을 지나는 진행 방향 선이다. 잉크(ink)는 실제로 전경색이 칠해지는 픽셀이며, 글자 사이 간격이나 이미지 텍스트의 배경은 포함하지 않는다.

그리기 함수는 로캘에 따라 글자 렌더링 순서를 뒤집을 수도(양방향), 이웃 글자에 따라 모양을 바꿀 수도(문맥 의존) 있다. 그래서 "두 글자를 한 번에 그린 결과"와 "한 글자씩 두 번 그린 결과"가 다를 수 있고, 글자를 끼워 넣으면 이웃 글자까지 다시 그려야 할 수 있다.

Bool XDirectionalDependentDrawing(XFontSet font_set);
Bool XContextualDrawing(XFontSet font_set);
Bool XContextDependentDrawing(XFontSet font_set);

각각 "방향 재배열을 하는가", "문맥 의존 모양 변경이 있을 수 있는가", "둘 중 하나라도 해당하는가"를 알려 준다.

또 하나 기억할 점: 그리기 함수는 줄바꿈, 탭 같은 제어 문자를 해석하지 않는다. 공백 이외의 비인쇄 문자를 그릴 때의 동작은 구현마다 다르다. 여러 줄 텍스트라면 클라이언트가 직접 줄을 나눠 줄마다 그려야 한다.

typedef struct {
    XRectangle max_ink_extent;      /* 그릴 수 있는 모든 글자에 대한 최대 잉크 영역 */
    XRectangle max_logical_extent;  /* 최대 논리 영역(간격 포함) */
} XFontSetExtents;

XFontSetExtents *XExtentsOfFontSet(XFontSet font_set);

목적: 폰트 세트 전체의 최대 글자 크기. XRectangle의 x, y는 원점 기준 왼쪽 위 모서리이고 너비·높이는 항상 양수다. 따라서 y는 보통 음수(기준선 위)다. max_logical_extent는 줄 간격이나 "글자 n개가 들어갈 입력란 크기"를 정할 때 쓴다. 반환 구조체는 Xlib 소유다.

int XmbTextEscapement(XFontSet font_set, char *string, int num_bytes);
int XwcTextEscapement(XFontSet font_set, wchar_t *string, int num_wchars);
int XmbTextExtents(XFontSet font_set, char *string, int num_bytes,
                   XRectangle *overall_ink_return, XRectangle *overall_logical_return);
int XwcTextExtents(XFontSet font_set, wchar_t *string, int num_wchars,
                   XRectangle *overall_ink_return, XRectangle *overall_logical_return);
  • ...Escapement: 원점에서 다음 글자의 원점까지의 거리(픽셀). 렌더링 순서와 관계없이 항상 양수다. 문자열 너비로 생각하면 된다.
  • ...Extents: 문자열 전체의 잉크 상자와 논리 상자를 채우고, escapement 값을 돌려준다. 필요 없는 쪽 인자는 NULL.
  • 길이 인자가 Xmb는 바이트 수, Xwc는 글자 수라는 점에 주의한다. UTF-8 "가"는 3바이트다.
  • 빠진 charset의 글자는 기본 문자열(default string)의 크기로 계산된다. 잘못된 코드포인트에 대한 동작은 정의되지 않았다.
Status XmbTextPerCharExtents(XFontSet font_set, char *string, int num_bytes,
        XRectangle *ink_array_return, XRectangle *logical_array_return,
        int array_size, int *num_chars_return,
        XRectangle *overall_ink_return, XRectangle *overall_logical_return);
/* XwcTextPerCharExtents 도 같은 모양 (wchar_t *, num_wchars) */

목적: 글자 하나하나의 잉크·논리 상자를 배열로 받는다. 커서 위치 계산, 마우스 클릭 위치를 글자 위치로 바꾸기 등에 쓴다. 배열이 작으면 0을 돌려주고 num_chars_return에 필요한 개수를 넣어 준다. 여러 글자가 하나의 글리프로 합쳐지면 그 글자들의 상자는 모두 같다.

13.4.6 폰트 세트로 텍스트 그리기 (Drawing Text Using Font Sets)

8장의 XDrawText/XDrawString/XDrawImageString과 비슷하지만, 폰트 하나 대신 폰트 세트를 쓰고 문자열 바이트를 "폰트 글리프 번호"가 아니라 로캘의 문자로 해석한다는 점이 다르다. GC의 font 값은 무시되며, 이 함수들이 GC의 폰트를 바꿔 놓을 수도 있다(그리기 뒤 같은 GC로 XDrawString을 쓸 때 주의). BadFont 오류가 나면 문제 글자 앞까지는 그려졌을 수 있다.

void XmbDrawString(Display *display, Drawable d, XFontSet font_set, GC gc,
                   int x, int y, char *string, int num_bytes);
void XwcDrawString(Display *display, Drawable d, XFontSet font_set, GC gc,
                   int x, int y, wchar_t *string, int num_wchars);
void XmbDrawImageString(Display *display, Drawable d, XFontSet font_set, GC gc,
                        int x, int y, char *string, int num_bytes);
/* XwcDrawImageString 도 같은 모양 */
  • ...DrawString: 전경색으로 글자만 그린다.
  • ...DrawImageString: 먼저 XmbTextExtents의 논리 상자만큼 GC 배경색으로 칠한 뒤 글자를 그린다. 텍스트를 덮어쓰며 갱신할 때 편하다.
  • (x, y)는 기준선 위의 원점이다. 글자 윗부분이 창 밖으로 잘리지 않게 하려면 y를 -max_logical_extent.y 이상으로 준다.
typedef struct {
    char     *chars;     /* 문자열 */
    int       nchars;    /* 바이트 수 */
    int       delta;     /* 이 항목 앞에 추가로 띄울 픽셀 */
    XFontSet  font_set;  /* None이면 앞 항목의 폰트 세트 유지 */
} XmbTextItem;           /* XwcTextItem 은 wchar_t *chars, nchars=글자 수 */

void XmbDrawText(Display *display, Drawable d, GC gc, int x, int y,
                 XmbTextItem *items, int nitems);

XmbDrawText는 여러 조각을 서로 다른 폰트 세트와 간격으로 이어 그린다. 맨 앞 항목들의 font_set이 None이면 그 항목들은 그려지지 않는다. 조각 사이에서는 문맥 의존 렌더링이 일어나지 않는다.

예제: UTF-8 한글 그리기 (Xutf8DrawString)

/* cc fontset.c -lX11 ;  LANG=ko_KR.UTF-8 ./a.out */
#include <locale.h>
#include <stdio.h>
#include <string.h>
#include <X11/Xlib.h>

int main(void)
{
    setlocale(LC_ALL, "");
    if (!XSupportsLocale()) { fprintf(stderr, "locale not supported\n"); return 1; }
    XSetLocaleModifiers("");

    Display *dpy = XOpenDisplay(NULL);
    if (!dpy) return 1;
    int scr = DefaultScreen(dpy);
    Window win = XCreateSimpleWindow(dpy, RootWindow(dpy, scr), 0, 0, 400, 120, 1,
                                     BlackPixel(dpy, scr), WhitePixel(dpy, scr));
    XSelectInput(dpy, win, ExposureMask | KeyPressMask);
    XMapWindow(dpy, win);

    char **missing; int nmissing; char *defstr;
    XFontSet fs = XCreateFontSet(dpy, "-*-*-medium-r-normal--16-*-*-*-*-*-*-*,*",
                                 &missing, &nmissing, &defstr);
    if (!fs) { fprintf(stderr, "XCreateFontSet failed\n"); return 1; }
    for (int i = 0; i < nmissing; i++)
        fprintf(stderr, "missing charset: %s\n", missing[i]);
    if (missing) XFreeStringList(missing);

    XFontSetExtents *ext = XExtentsOfFontSet(fs);
    int line_h = ext->max_logical_extent.height;
    int ascent = -ext->max_logical_extent.y;     /* 기준선 위 높이 */

    GC gc = DefaultGC(dpy, scr);
    const char *msg = "안녕하세요, X11!";
    for (;;) {
        XEvent ev;
        XNextEvent(dpy, &ev);
        if (ev.type == Expose && ev.xexpose.count == 0) {
#ifdef X_HAVE_UTF8_STRING
            Xutf8DrawString(dpy, win, fs, gc, 10, 10 + ascent, msg, strlen(msg));
#else
            XmbDrawString(dpy, win, fs, gc, 10, 10 + ascent, (char *)msg, strlen(msg));
#endif
            XRectangle ink, logical;
            XmbTextExtents(fs, (char *)msg, strlen(msg), &ink, &logical);
            /* 문자열 아래에 너비만큼 밑줄 */
            XDrawLine(dpy, win, gc, 10, 12 + line_h, 10 + logical.width, 12 + line_h);
        } else if (ev.type == KeyPress) break;
    }
    XFreeFontSet(dpy, fs);
    XCloseDisplay(dpy);
    return 0;
}
흔한 함정
  • 폰트 세트는 서버의 코어 폰트(비트맵 XLFD 폰트)를 쓴다. 요즘 시스템에는 한글 코어 폰트가 설치돼 있지 않은 경우가 많아, 빠진 charset이 나오고 한글이 기본 문자열(빈칸 등)로 나올 수 있다. 이때는 xlsfonts | grep -i ksc, iso10646 폰트 설치 여부를 확인한다. 안티앨리어싱된 현대적 글꼴이 필요하면 Xft/fontconfig 같은 별도 라이브러리를 쓰는 것이 일반적이다(이 매뉴얼 범위 밖).
  • num_bytes에 글자 수를 넣는 실수. Xmb/Xutf8는 바이트 수(strlen)다.
  • 폰트 세트를 만든 뒤 로캘을 바꿔도 폰트 세트는 옛 로캘로 해석한다.

13.5 입력 방법 (Input Methods)

13.5.1 개요: 왜 입력기가 필요한가

알파벳 언어는 키보드에 없는 몇몇 글자(악센트 등)만 여러 키 조합으로 넣으면 된다(유럽식·compose·dead-key 입력). 한국어 한글은 자음 14개, 모음 10개의 기본 자모를 조합해 음절을 만드는데, 두 번째·세 번째 자모가 들어올 때마다 앞 자모의 모양과 크기가 바뀌며 화면에 보이는 글자가 계속 변한다. 일본어(가나→한자 변환), 중국어(병음 등 수십 가지 방식)처럼 수천~수만 자의 표의 문자를 쓰는 언어는 키보드로 직접 칠 수 없으니, 소리나 모양으로 입력한 뒤 후보 중에서 고르는 단계가 필요하다. 원문은 한국어에서도 한글을 한자로 바꾸는 변환을 예로 든다.

이처럼 여러 키 입력으로 글자를 조립하는 과정을 미리 편집(preediting)이라고 한다. 입력기는 다음 화면 영역을 쓸 수 있다.

  • 상태 영역(status area): 키보드 LED의 연장. 한/영 상태 같은 입력기 내부 상태를 보여 준다.
  • 미리 편집 영역(preedit area): 아직 확정되지 않은 조합 중 글자를 보여 준다.
  • 보조 영역(auxiliary area): 후보 목록 같은 팝업. 입력기가 혼자 관리한다.

미리 편집을 어디에 보여 주느냐에 따라 입력 스타일이 나뉜다.

스타일뜻대응 XIMStyle
on-the-spot응용 창의 커서 위치에 직접 표시. 응용이 콜백으로 직접 그린다.XIMPreeditCallbacks
over-the-spot입력 위치 위에 입력기가 창을 띄워 표시XIMPreeditPosition
off-the-spot응용 창 안의 별도 영역(보통 아래쪽)에 표시XIMPreeditArea
root-window루트 창의 자식 창에 표시(응용은 아무것도 안 함)XIMPreeditNothing

모든 언어의 입력기를 모든 응용에 넣을 수는 없으므로, 입력기를 별도 프로세스인 입력 서버(input server)로 두고 응용이 그와 통신하게 하는 것이 Xlib 설계 목표다(오늘날의 ibus, fcitx, nimf 등이 XIM 서버 역할을 한다). 구조는 두 가지다.

  • front-end: 키 입력은 X 서버에서 입력기로 직접 가고, 입력기가 조립한 문자열을 클라이언트에 보낸다. 연결이 둘이라 동기화 문제가 있지만 프로세스 전환은 적다.
  • back-end: 연결은 하나이고, 클라이언트 쪽에서 키를 입력기에 넘겨준다. 통신·프로세스 전환이 더 많다(같은 기계에서 키 하나당 전환 두 번).

어느 쪽이든 클라이언트는 네트워크 라이브러리를 직접 쓸 필요 없이 XIM 객체만 다루면 된다. 입력 서버가 여러 언어를 지원하더라도, 돌려받는 문자열은 항상 XIM에 묶인 하나의 로캘로 인코딩된다.

입력 문맥(XIC)과 포커스

입력 문맥 XIC는 입력 "흐름" 하나의 상태다. 입력 방법, 돌려줄 문자열의 로캘, 클라이언트 창, 내부 상태, 모양 설정 등을 묶은 것으로, 출력의 GC에 대응하는 개념이라고 보면 된다. XIC 하나는 정확히 하나의 XIM에 속하며, XCloseIM 뒤에는 거기 속한 XIC를 쓰면 안 된다(가능하면 먼저 없앤다). 입력란이 여러 개라면 입력란마다 XIC를 하나씩 만들 수도, 최상위 창에 하나만 만들고 입력란을 옮길 때마다 문맥 값을 바꿀 수도 있다.

응용 안에서 포커스가 어떤 입력란으로 오면 XSetICFocus, 나가면 XUnsetICFocus를 부른다. 서로 다른 두 XIC에 연달아 XSetICFocus를 부르면 앞의 것은 자동으로 해제된다. 이 "응용 수준의 포커스"는 X 서버의 포커스와 반드시 같지는 않으므로 응용이 직접 추적해야 한다.

기하 관리와 이벤트 걸러내기 (개념)

off-the-spot처럼 입력기 영역을 응용 창 안에 넣을 때는 역할 분담이 원칙이다: 창의 위치·크기는 클라이언트가, 내용은 입력기가 책임진다. 입력기는 크기를 제안만 할 수 있고, 위치는 제안할 수 없으며, 주어진 크기를 받아들여야 한다. 협상 순서는 ① 클라이언트가 XNAreaNeeded로 제약을 제안 ② XNAreaNeeded를 읽어 입력기의 희망 크기를 받음 ③ XNArea로 실제 영역을 알려 줌이다. XNFontSet, XNLineSpace를 바꾸면 희망 크기가 바뀔 수 있으니 다시 협상해야 한다.

입력기는 키 이벤트나 자기 창의 Expose, 입력 서버와의 통신용 이벤트 등을 클라이언트 몰래 가로채야 한다. 그래서 Xlib은 이벤트 필터를 두고, 클라이언트는 모든 이벤트를 XFilterEvent에 먼저 넘겨야 한다. 또 XIC 값 XNFilterEvents로 입력기가 필요로 하는 이벤트 마스크를 받아 자기 창의 이벤트 마스크에 더해야 한다(0일 수도 있다).

콜백, 문자열 변환, 핫키, 미리 편집 상태 (요약)

on-the-spot에서는 조합 중 글자를 응용이 직접 그려야 하므로, 입력기가 XmbLookupString 처리 도중 응용에 "이 글자를 그려라"라고 되부르는(callback) 구조가 된다. 이 밖에 상태 표시 콜백, 기하 변경 요청 콜백도 있다. 긴 미리 편집 문자열 중 꼭 보여야 할 부분을 알려 주는 가시 위치 피드백 마스크도 있다.

문자열 변환(string conversion)은 이미 응용 버퍼에 있는 텍스트를 입력기가 다루게 하는 틀이다. 예: 이미 쳐 놓은 한글을 한자로 바꾸기(음역 변환), 확정된 문자열을 다시 변환하기(재변환), 태국어처럼 커서 주변 글자를 보고 입력을 검사하는 문맥 의존 변환. 클라이언트가 요청하는 XNStringConversion과, 입력기가 필요할 때 클라이언트에 텍스트를 달라고 부르는 XNStringConversionCallback 두 방식이 있다.

핫키(XNHotKey)는 입력기 상태와 관계없이 응용이 가로챌 키(도움말 키, 포커스 이동 키 등)를 지정하는 기능이고, 미리 편집 상태(XNPreeditState)는 조합 기능이 켜져 있는지(XIMPreeditEnable/XIMPreeditDisable)를 읽고 바꾸는 기능이다. 이것들은 모두 선택 기능이라, 쓰기 전에 XGetIMValues(im, XNQueryICValuesList, ...)로 지원 여부를 확인해야 한다.

입력 방법 관리 (Input Method Management)

X 서버, 입력 서버, 클라이언트가 제각각 시작되면, 클라이언트가 입력 서버보다 먼저 떠서 연결에 실패할 수 있다. 입력 서버가 중간에 죽거나 바뀔 수도 있다. 이를 위해 다음이 마련돼 있다.

  • XRegisterIMInstantiateCallback: 맞는 입력 서버가 나타나면 불릴 콜백을 등록한다. 콜백 안에서 XOpenIM을 부르면 된다.
  • XNDestroyCallback(IM/IC 값): 입력 서버가 사라질 때 불린다.
  • XUnregisterIMInstantiateCallback: 등록 해제.

void CallbackPrototype(XIC ic, XPointer client_data, SomeType call_data);

13.5.7 이벤트 걸러내기 (Event Filtering)

Bool XFilterEvent(XEvent *event, Window w);

목적: 이벤트를 입력기 필터에 먼저 보여 준다. XNextEvent 직후에 부른다.

  • w: 필터를 적용할 창. None이면 이벤트 구조체 안의 창을 쓴다. 이벤트를 다른 창으로 돌려 보내는 상위 계층(툴킷)을 위해 있는 인자다.
  • True면 입력기가 이벤트를 가져갔으니 클라이언트는 그 이벤트를 버린다. False면 평소처럼 처리한다.
  • 클라이언트가 grab 중이었는데 True가 나오면 키보드 grab을 풀어야 한다.
XIM을 쓰는 프로그램이 XFilterEvent를 빼먹으면, 입력기 창이 나타나지 않거나 한글이 전혀 조합되지 않는다. 또 True가 나온 KeyPress를 계속 처리하면 "ㅎ"과 "한"이 둘 다 들어가는 식의 중복 입력이 생긴다.

13.5.8 키보드 입력 받기 (Getting Keyboard Input)

int XmbLookupString(XIC ic, XKeyPressedEvent *event, char *buffer_return,
                    int bytes_buffer, KeySym *keysym_return, Status *status_return);
int XwcLookupString(XIC ic, XKeyPressedEvent *event, wchar_t *buffer_return,
                    int wchars_buffer, KeySym *keysym_return, Status *status_return);
/* libX11 확장: Xutf8LookupString 은 XmbLookupString 과 같은 모양, 결과가 UTF-8 */

목적: 입력기가 조립한 문자열(그리고/또는 KeySym)을 받는다. 11장의 XLookupString의 국제화판이다.

  • 반환값: Xmb는 바이트 수, Xwc는 글자 수. 문자열은 널 문자로 끝나지 않으므로 직접 붙여야 한다.
  • keysym_return: NULL이 아니고 상태가 KeySym을 돌려줬다고 할 때만 유효. 문자열과 KeySym을 같이 받았을 때 둘이 반드시 대응하지는 않는다.
  • KeyPress 이벤트만 넘긴다. KeyRelease를 넘기면 동작이 정의되지 않는다.
  • 입력 문맥이 지금 포커스를 갖고 있는지는 상관없다. 포커스를 잃기 전에 조립된 입력이 나중에 나올 수 있다.

status_return 값을 먼저 보고 나머지를 써야 한다.

status뜻
XBufferOverflow버퍼가 작다. 필요한 크기가 반환값으로 오며, 버퍼와 KeySym은 바뀌지 않는다. 같은 이벤트로 더 큰 버퍼를 주고 다시 부른다.
XLookupNone아직 완성된 입력이 없다(조합 중). 반환값 0.
XLookupChars문자열이 왔다. KeySym은 바뀌지 않는다.
XLookupKeySym문자열 대신 KeySym만 왔다(화살표, F1 등). 반환값 0.
XLookupBoth문자열과 KeySym이 둘 다 왔다.

13.5.9 입력 방법 관례 (Input Method Conventions)

  • 클라이언트 관례: 잘 만든 클라이언트는 먼저 입력 스타일을 조회하고, 요구 사항(기하 관리, 콜백)을 감당할 수 없으면 사용자와 협의하거나 오류를 낸다.
  • 동기화 관례: KeyCode가 0인 KeyPress 이벤트는 "입력기가 조립한 입력이 준비됐으니 XmbLookupString으로 가져가라"는 신호로만 쓰인다. 입력 서버가 보낸 합성 이벤트, 필터가 큐에 넣은 이벤트 등으로 생긴다. 그러니 "KeyCode 0은 쓸모없는 이벤트"라며 버리면 안 된다.
  • 콜백을 지정했다면, 입력기는 클라이언트를 명시적으로 불렀는데 응답이 없을 때(콜백 미지정, 잘못된 데이터)만 스스로 행동한다.

예제: 가장 단순한 XIM 입력 (Xutf8LookupString)

/* cc xim.c -lX11 ;  LANG=ko_KR.UTF-8 XMODIFIERS=@im=ibus ./a.out */
#include <locale.h>
#include <stdio.h>
#include <stdlib.h>
#include <X11/Xlib.h>
#include <X11/Xutil.h>
#include <X11/keysym.h>

int main(void)
{
    setlocale(LC_ALL, "");
    if (!XSupportsLocale()) { fprintf(stderr, "locale not supported\n"); return 1; }
    if (!XSetLocaleModifiers("")) fprintf(stderr, "cannot set modifiers\n");

    Display *dpy = XOpenDisplay(NULL);
    if (!dpy) return 1;
    int scr = DefaultScreen(dpy);
    Window win = XCreateSimpleWindow(dpy, RootWindow(dpy, scr), 0, 0, 300, 100, 1,
                                     BlackPixel(dpy, scr), WhitePixel(dpy, scr));

    /* 1) 입력 방법 열기. 실패하면 내장 입력(@im=none)으로 재시도 */
    XIM im = XOpenIM(dpy, NULL, NULL, NULL);
    if (!im) {
        XSetLocaleModifiers("@im=none");
        im = XOpenIM(dpy, NULL, NULL, NULL);
    }
    if (!im) { fprintf(stderr, "XOpenIM failed\n"); return 1; }

    /* 2) 지원 스타일 중 PreeditNothing|StatusNothing 찾기 */
    XIMStyles *styles = NULL;
    XIMStyle want = XIMPreeditNothing | XIMStatusNothing, style = 0;
    if (XGetIMValues(im, XNQueryInputStyle, &styles, NULL) == NULL && styles) {
        for (int i = 0; i < styles->count_styles; i++)
            if (styles->supported_styles[i] == want) style = want;
        XFree(styles);
    }
    if (!style) style = XIMPreeditNone | XIMStatusNone;   /* 차선책 */

    /* 3) 입력 문맥 만들기 */
    XIC ic = XCreateIC(im, XNInputStyle, style,
                       XNClientWindow, win,
                       XNFocusWindow, win,
                       NULL);
    if (!ic) { fprintf(stderr, "XCreateIC failed\n"); return 1; }

    /* 4) 입력기가 원하는 이벤트를 내 마스크에 더하기 */
    unsigned long fevents = 0;
    XGetICValues(ic, XNFilterEvents, &fevents, NULL);
    XSelectInput(dpy, win, ExposureMask | KeyPressMask | FocusChangeMask | fevents);
    XMapWindow(dpy, win);

    char sbuf[64], *buf = sbuf;
    int bufsize = sizeof sbuf;
    for (;;) {
        XEvent ev;
        XNextEvent(dpy, &ev);
        if (XFilterEvent(&ev, None)) continue;          /* 입력기가 가져감 */

        if (ev.type == FocusIn)  XSetICFocus(ic);
        if (ev.type == FocusOut) XUnsetICFocus(ic);
        if (ev.type != KeyPress) continue;

        KeySym ks = NoSymbol;
        Status st;
        int len = Xutf8LookupString(ic, &ev.xkey, buf, bufsize - 1, &ks, &st);
        if (st == XBufferOverflow) {                     /* 큰 버퍼로 재시도 */
            bufsize = len + 1;
            buf = (buf == sbuf) ? malloc(bufsize) : realloc(buf, bufsize);
            len = Xutf8LookupString(ic, &ev.xkey, buf, bufsize - 1, &ks, &st);
        }
        if (st == XLookupChars || st == XLookupBoth) {
            buf[len] = '\0';                             /* 널로 끝나지 않으니 직접 */
            printf("입력: %s\n", buf);
        }
        if ((st == XLookupKeySym || st == XLookupBoth) && ks == XK_Escape)
            break;
    }
    XDestroyIC(ic);          /* IC 먼저, IM 나중 */
    XCloseIM(im);
    XCloseDisplay(dpy);
    return 0;
}
점검 목록
  • XOpenIM이 NULL: 로캘이 "C"이거나, XMODIFIERS가 가리키는 입력 서버가 떠 있지 않은 경우가 대부분이다. 위 예제처럼 @im=none으로 재시도하면 최소한 영문·compose 입력은 된다. 입력 서버가 나중에 뜰 수 있는 환경이면 XRegisterIMInstantiateCallback을 쓴다.
  • 한글이 조합되지 않음: XFilterEvent 누락, XNFilterEvents 마스크 누락, XSetICFocus 누락을 차례로 확인한다.
  • Over-the-spot(XIMPreeditPosition)을 쓰면 커서가 움직일 때마다 XNPreeditAttributes 중첩 목록으로 XNSpotLocation을 갱신해야 입력 창이 커서를 따라온다(13.3의 예 참고).
  • XNClientWindow는 한 번만 설정할 수 있다. 창을 바꾸려면 IC를 새로 만든다.
